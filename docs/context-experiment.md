# 上下文管理与拒答实验（第 7 周）

## 1. 实验设置
- 生成模型：deepseek-chat
- Embedding：智谱 embedding-3，1024 维
- 索引：10 篇文档，81 块，semantic 500/50
- 评测集：25 条（fact 9 / multi_hop 7 / unanswerable 5 / trap 4）
- token 估算已按 0.85 中文系数校准（详见下节）

## 2.token 估算校准
- 模型：deepseek-chat
- 样本：同一问题，1/5/6 个 semantic 块
- 校准前：估算/真实 = 1.358 / 1.270 / 1.276（高估约 27%）
- 调整：中文系数 1.0 → 0.85（保留约 8% 安全余量）
- 校准后：估算/真实 = 1.175 / 1.103 / 1.108
- 结论：保留 0.85；1.10 是刻意保留的安全边际
- 索引已重建，chunk.token_estimate 同步更新
- 局限：只测了中文 Markdown；completion 仅 51–63 token，answer_reserve=800 偏保守

## 3. 拒答测试（9 条）

| 类型 | 条数 | 正确拒答/纠正 | 只拒答不纠正 | 顺着错误前提答 |
|---|---|---|---|---|
| unanswerable | 5 | 5 | — | — |
| trap | 4 | 4（均明确说“不对”，并给出资料中的正确说法，带引用） | 0 | 0 |

说明：
- unanswerable 的 `abstained=True` 即正确拒答，5/5。
- trap 的正确行为是“纠正错误前提”，不是拒答；因此 4 条 trap 的 `abstained=False` 是预期结果。
- trap 的 4 条回答都带有引用（1/1/2/3 条），说明模型确实读了资料，而不是凭先验判断。

## 4. 上下文管理对比（16 条可回答题）

| 配置 | top_k | 预算 | prompt token 均值 | 延迟均值 | 引用覆盖率 | 引用总数 | 无效编号 | 可回答题误拒 |
|---|---|---|---|---|---|---|---|---|
| A 固定 top-5 | 5 | — | 1023 | 1140 ms | 15/16（93.8%） | 28 | 0 | 1（q025） |
| B 预算 8000 | 8 | 8000 | 1462 | 1209 ms | 15/16（93.8%） | 33 | 0 | 0* |
| C 预算 4000 | 8 | 4000 | 1462 | 1237 ms | 16/16（100%） | 35 | 0 | 2（q023、q025）** |

\* B 的 q025 实际是“改写版拒答”（“资料中没有提到……无法据此解释”），但未命中固定话术，因此 `abstained=False`。这是指标假阴性，不代表它真的回答了。
\** C 的 q023 是“假拒答”：回答完整且带 5 条引用，但结尾追加了“未找到相关内容。缺少：个人情况”，被正则误判。C 的 q025 是带引用的拒答。

## 5. 结论

### 5.1 主要发现

1. **B 和 C 没有形成有效对比。** 两组 prompt token 均值都是 1462，因为 4000 预算扣除预留后仍有 2600 token，而 top-8 块合计约 1000–1200 token，预算没有成为约束。因此本实验实际比较的是“A 的 5 条”与“B/C 的 8 条”，不能据此得出“4000 比 8000 差”的结论。

2. **A 最便宜，但证据更少。** A 的 prompt token 均值 1023，比 B/C 低约 43%；延迟 1140 ms，略低。代价是只送 5 条，引用总数 28，且在 q025 上直接拒答。

3. **B 比 A 多送 3 条，成本上升约 43%，但没有带来可观察的引用准确率提升（尚未人工抽检）。** 它的主要收益是 q025 不再触发固定话术拒答，但仍然以“资料中没有提到”的形式拒答，说明增加上下文没有解决“需要跨段推理”的问题。

4. **trap 表现很好。** 4/4 都明确纠正了错误前提，并带引用；unanswerable 5/5 正确拒答。说明提示词的三条硬约束和编号制引用在拒答场景下有效。

5. **`abstained` 指标本身不可靠。** C 的 q023 是假阳性（完整回答 + 结尾追加拒答话术），B 的 q025 是假阴性（改写版拒答未命中固定前缀）。后续应改为“只看开头是否以 ABSTAIN_PREFIX 开始”，或结合“是否有有效引用/是否给出事实”判断。

### 5.2 选型建议

- **默认配置选 B（top-8，预算 8000，by_budget_with_floor）**：在成本增加约 43% 的情况下，证据覆盖更全，且没有固定话术误判。
- **成本敏感场景选 A（top-5，不裁剪）**：更便宜、更快，但要接受 q025 这类需要跨段推理的题更容易拒答。
- **C（4000）暂不作为结论依据**：它没有真正限制住上下文。若要验证更紧的预算，应补一组 `total=2000`（available=600）或使用严格的 `by_budget` 策略，再重新跑。

### 5.3 待修正项

> 本节记录实验暴露的问题与处理状态。`[x]` 表示已完成，`[ ]` 表示待办。

#### 已完成

- [x] **人工抽检 A/B/C 的引用准确率**
  已完成抽检：A 抽检 5 条 → 5/5（100%）；B 全量 16 条 → 15/16（93.8%）；
  C 抽检 5 条 → 5/5（100%）。
  唯一不支持的样本是 q010——答案陈述正确，但额外引用了 [5]「三、判断一件事值不值得做」
  与 [6]「六、最后一句」，属冗余引用。
  局限：A、C 各仅抽检 5 条，B 为 16 条全量，抽检量不对等，
  6.2 个百分点的差距不足以判定 B 的引用质量真的更差；且抽检由本人完成，存在主观偏差。

- [x] **复核 q025 的失败原因**
  已确认**不是检索未召回**。实测检索 top-20，覆盖 gold_span 的两个块分别排在第 2 位（相似度 0.642，
  「预算有限时，把钱花在磨豆机上……远大于壶嘴的形状」）和第 5 位（相似度 0.595，
  「不要急着换豆子、换器具、换配方。先把手上的这套流程重复二十次」）。
  两者均已在 top-5 内，说明失败发生在**生成阶段的跨块综合**：
  正确答案需要合并「磨豆机比壶重要」与「前二十杯不好喝属正常、别急着换器具」两条信息。
  因此修复方向在生成侧（prompt 引导多块综合）与排序侧（rerank 使相关块进入前 3），
  而非加大 top_k——top-8 已证明无法解决。

- [x] **改进 `abstained` 判定**
  初版使用 `search()` 全文匹配固定话术，实测暴露两个方向的错误：
  （1）**假阳性**：q023 给出了完整回答，仅因结尾追加「未找到相关内容。缺少：个人情况」被误判为拒答；
  （2）**假阴性**：q025 的改写版拒答「资料中没有提到……无法据此解释」未命中固定话术，被判为已回答。
  修正方案改为「**开头匹配 + 去话术后剩余内容 < 80 字**」双重条件，
  并将话术表从 1 条扩充到 7 条（未找到相关内容 / 资料中没有提到 / 资料中未提到 /
  资料未涉及 / 没有相关资料 / 资料不足 / 无法回答）。
  修正后 q023 判为回答、q025 判为拒答，与人工判定一致；
  同时新增「拒答样本却含引用」的日志留痕，便于后续抽查。
  注意：修正前后的拒答统计不可直接比较，`data/experiments/refusal.json` 已用新判定重跑。

#### 待办

- [ ] **补一组真正有约束力的预算实验**
  现有 A(8000)/B(4000) 未形成有效对比：4000 预算扣除预留（system 400 + answer 400 + question 200）
  后仍有 2600 token，而 top-8 块合计仅约 1280 token，预算未成为约束。
  约束生效的临界值是 `total < 2280`（因为 available < 1280 时才会开始丢弃块）。
  计划补两组：

  | 配置 | total | available | 预估实塞块数 | 目的 |
  |---|---|---|---|---|
  | D | 2000 | 1000 | 约 6 块 | 轻度约束 |
  | E | 1600 | 600 | 约 3 块 | 强约束 |

  执行时必须使用严格截断策略 `by_budget` 而非 `by_budget_with_floor`
  ——后者含 `min_chunks=3` 保底，可能反而超预算，测不出约束效果。
  验证方式：跑完后检查 prompt token 均值是否显著低于 B 的 1462；
  若未下降，说明预算仍未生效，需继续调小。
  该实验要回答的核心问题是：**更小的上下文是否伤害答案质量**——
  若 600 token 能取得与 1460 token 相当的质量，即意味着成本可降约 60%。

- [ ] **引用粒度精确到句**
  当前 `Citation.quote` 是**整个检索块**（280~500 字符），而非支持该陈述的具体句子。
  表现为：答案引「88–94℃ [2]」，但展示给用户的是 282 字的整节「二、四个核心变量」，
  用户需自行定位支持句。
  这不影响引用的"正确性"，但明显损害可用性，且使引用准确率的判定口径偏松
  （整块中存在支持句即算支持）。
  计划方案：在块内按句切分，逐句与答案句计算相似度取最高者，
  `quote` 只展示该句，并新增 `quote_start_char` / `quote_end_char` 精确定位。
  预计在第 8 周作为选做项完成。

- [ ] **约束 prompt 中的冗余引用**
  q010 的 6 条引用中有 2 条（[5]「三、判断一件事值不值得做」、[6]「六、最后一句」）
  与陈述关系很弱，属「相关但不直接支持」的引用。
  推测成因：prompt 要求「每个事实性陈述后必须标注资料编号」，
  模型倾向于多标以防漏标。
  计划改进：在 prompt 中补充「只标注**直接支持**该句的资料，不要标注相关但不能直接支撑的资料」，
  并在第 8 周的引用准确率指标中区分「必要引用」与「冗余引用」。
