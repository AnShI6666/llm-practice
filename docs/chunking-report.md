# 分块策略对比实验报告

## 1. 实验目的
为了给 RAG 系统选择最优的文本切分方案，本实验对比了固定长度（Fixed）、语义结构（Semantic）、递归（Recursive）三种分块策略在不同参数下的表现。测试集包含 10 篇真实的 Markdown 文档。

## 2. 核心指标说明
- **截断率**：块的开头或结尾被生硬切断的比例（越低越好，防止语义破损）。
- **平均标题数**：块内包含的标题数量，用于近似衡量语义凝聚力（越接近 1 越好）。
- **长度标准差**：块大小的波动范围（越小说明块长越均匀，利于批处理控制 Token）。

## 4. 深度数据分析
从数据中可以得出非常明显的结论：
1. **Fixed 策略（基线）极差**：截断率高达 91%~100%。因为它完全无视句法和结构，只会按字符数硬切。切出来的块不仅语义破碎，且块内平均夹杂了 0.2~0.4 个标题，说明它经常跨章节拼接，导致语义严重污染。
2. **Semantic 策略表现最佳**：截断率骤降至 20%~27%。由于它严格遵守 Markdown 标题边界，块内的标题平均数降到了极低的 0.09，说明**完全没有跨章节混词**。代价是块数变多（106 块），因为很多段落本身就短。
3. **Recursive 策略（初版实现）存在缺陷**：虽然理论上递归分块最完美，但本次手写实现中，由于未加入高级的小块合并逻辑，导致切分过碎（平均块长仅 96），截断率反而升高（79%）。这暴露了朴素递归算法在处理复杂换行时的局限性。

## 5. 最终结论与选型
基于以上数据，**本项目第 5 周最终选择 `Semantic`（语义分块）策略，参数为 `chunk_size=500, overlap=50`。**
- **为什么选它**：在本次实现中，它拥有最低的截断率（22.6%）和最好的语义凝聚力（标题混杂度最低）。
- **放弃了什么**：放弃了 `Fixed` 极高的块长均匀度。`Semantic` 切出来的块长短不一（标准差 103），这意味着后续在向大模型发送上下文时，无法使用绝对固定的 Token 预算，需要动态计算。

## 6. ⚠️ 实验局限性与诚实声明
必须坦诚说明：**本实验的指标（如标点截断率）属于启发式的“代理指标”，不能直接等同于最终的大模型检索命中率。**
真正的分块优劣，必须等到第 7 周接入向量检索、第 8 周构建 50 条真实评测集后才能盖棺定论。当前的量化实验，仅用于排除明显最差的选项（即证实了 Fixed 策略不可用）。
